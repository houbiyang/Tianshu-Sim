# 史料语料库

把 `.md` 文件放进这个目录，应用会自动索引（无需改名、无需注册、无需重启）。
地图页右上「📚 史料库」显示当前索引了多少个文件、多少个片段。

## 会被索引的文件

- 本目录及子目录下的所有 `.md`
- 文件名不以 `_` 或 `.` 开头

## 不会被索引

- `README.md`（就是本文件，防止把格式说明当成史料检索出来）
- 以 `_` 或 `.` 开头的文件（临时草稿可以这样命名）

## 文件格式

只有一个硬约定：**用二级标题 `##` 切分片段**，每个 `##` 就是一个可被独立检索、独立引用的单元。
一级标题 `#` 作为来源名显示。

```markdown
# 战役名称（会作为来源名，如「长平之战」）

## 战役定位
这里写时间、地点、交战方、出处。

## 兵力与伤亡
这里写数字。**凡是史料没给的数字，请明确写「史料未载」。**

## 关键时间线
按顺序写可考节点。
```

片段越短越聚焦，检索越准。一个 `##` 建议控制在 200—600 字。

## 三条写作纪律

1. **有出处**。写清引自哪本书、哪一篇。没有出处的数字，标注「后世估算」。
2. **区分「史料记载」与「学界争议」**。例如长平「四十万」既是《史记》原文，也是有争议的数字，两者都要写，否则模型会把争议数字当成确证使用。
3. **别写推演结论**。语料是事实，不是战术建议；战术判断交给模型。

## 检索是怎么工作的

- 纯本地 BM25（词频—逆文档频率），**不联网、不调用任何 API、不产生费用、不需要 Key**。
- 中文按字符二元组切词，英文与数字按词切。没有分词词典，所以新出现的人名地名也不会失配。
- 索引按文件修改时间自动失效重建。改完文件，下一次推演就生效。
- 语料为空或检索零命中时，界面会明确提示「本次仍为模型自由发挥」，**不会静默降级**。

## 建议的组织方式

一场战役一个文件，文件名用战役名。跨战役的通用资料（如某朝代军制、某类武器的射程考据）单独建文件，检索时会被自动带出。

也可以按来源建文件，例如 `史记-白起王翦列传.md`，一个 `##` 对应一段原文摘录 + 白话说明。
