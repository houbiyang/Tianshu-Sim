# 战棋指挥与 DSH 智能体开发规划

确认日期：2026-10-24。基线：v3.2.1，提交 `a385a37`。

状态：用户已确认交互方向与 DSH 优先原则；M0—M4 已按本文范围实施，功能与验收记录见第11节。以 Vue/Electron 桌面入口为首批交付对象，复用现有 FastAPI、Leaflet、DSH 原生插件和标准库裁决模块。原 Streamlit 入口保持可用，共享规则不得产生相互矛盾的结果。

## 1. 目标与开发约束

实现“选择单位—选择行动—地图选点—自然语言补充—命令排队—回合执行—决策复盘”的战棋操作闭环。地图和自然语言只是不同输入入口，必须形成同一种命令，经过同一套校验与执行流程。

后续开发按以下约束推进：

1. **DSH 优先，禁止另建通用智能体框架。** 会话、角色记忆、子 Agent 生命周期、工具注册、事件、取消、模型分支、预算控制先使用已安装 DSH 的实际接口；不得再实现一套聊天传输、通用 Agent 调度器、会话数据库、工具调用循环或运行时插件系统。
2. **应用只承担领域职责。** 单位身份、控制权限、命令语义、资源与规则校验、命令冲突、程序目标、权威战局和执行回执属于战棋业务，不交给模型自行维护，也不误称为重复实现 DSH。
3. **唯一权威状态。** DSH 智能体读取决策前快照、提出候选；应用校验并统一提交。每个智能体不能另存一份可自行写入的人员、装备和库存账。
4. **命令不等于结果。** 下令不直接改坐标、补给、伤亡或时间；意图、候选、已确认命令、执行事实分开显示。
5. **不改变现有用户数据。** 开发与验收使用隔离目录，不覆盖现有模型配置、Vault 密钥、对局、轨迹、DSH 全局配置及本机安装程序。旧存档采用增量兼容，不能静默重置。
6. **保持模型质量设置。** 不为降低延迟而调低已有思考强度或擅自修改用户预算；沿用角色策略与 64k 引擎预算，实际请求设置可核验。

本规划不新增真实道路寻路、DEM视线遮挡、完整通信损耗或历史标定战损模型。需要这些机制的动作应标为未支持或不可核验，不能以界面按钮替代算法。

## 2. v3.2.1基线与本次工作

| 部分 | v3.2.1基线 | 本次实施范围（完成记录见第11节） |
| --- | --- | --- |
| 地图 | `MapView.vue` 画军标、只读弹窗、轨迹、火力及补给图层 | 受控单位选择、行动选项、地图目标拾取、预览与事件回传 |
| 指挥 | `next` 接受本轮意图字符串；`chat` 只读问答 | 统一结构化命令、权限、冲突、时效、编辑和撤销 |
| 固定演习 | `missions.advance` 接收单位命令，计算库存、损失与目标 | 用户命令覆盖规划、持续移动任务及完整执行回执 |
| 普通开放推演 | 模型生成候选状态，执行守恒、时钟、射界等检查 | 指令履行检查；不能把事后位移告警当成硬执行器 |
| 决策展示 | 每回合模型声明与DSH事件引用 | 去除最多6条生成、16条采纳的覆盖缺口，逐单位记录 |
| 单位身份 | 多处以“方别＋名称”关联 | 稳定ID、旧存档映射、退役记录和命令失效处理 |
| DSH | 持久角色会话、原生工具、事件、取消与原生分支 | 复用这些能力接入指挥解析、单位规划及观测 |

当前统一引擎为单位生成行动，不等于每个单位已经拥有独立智能体。现有多个单位可能共用一句总体决策理由；后续必须拆分总体部署依据和本单位依据。

| 模型反事实 | `fork_run` 与现有精确决策前事件边界分支 | 命令干预、对照指标及独立分析产物 |
| 轨迹与提交 | `extensions`、`plugins/runtime.json` 和现有提交前钩子 | 单位命令、执行回执、规则检查和状态变化的关联 |
| 确定性命令对照 | `missions.counterfactual` 与现有纯函数规则 | 对照命令选择界面；不必为无模型重算创建DSH会话 |

### 3.1 接口与插件边界

- 不能因为 DSH 内核或 Web 文档出现某方法，就假定当前 Python SDK 已暴露。当前版本对原始 `client.request('session/cancel')`、`session/fork` 的既有探测为不支持；继续复用项目 Cordis 插件适配，不能重走同一错误路径。
- 新领域工具沿用既有 `runtime_bridge` 的脱离主状态快照和认证本机通道，不另建通用工具服务器。
- 模型工具保持观察、检索、可行性检查和候选建议性质。模型不得通过工具直接确认用户命令、改写战局、增加兵员或绕过权限。
- 人类的命令确认与回合提交经应用API执行。该领域授权边界不能因“充分使用DSH”而移交给模型。
- 运行时扩展优先通过现有 Cordis 插件与应用钩子；只有明确的领域隔离需求才拆插件包，不重复建设插件注册平台。
- 维持 Native、`sdk-minimal` 和项目级启动补丁；本功能不需要 PTC 或模型生成代码执行，也不恢复 shell、编辑器、Office、浏览器等无关能力。
- 当前 JSON 工具兼容模式保留为明确选项；原生运行失败必须报告，不能悄悄切换后仍显示“原生成功”。

### 3.2 调用与延迟原则

点击单位、菜单选择、选点、显示距离、确认格式明确的手动命令均不调用模型。自然语言解析和自主规划复用同一个DSH调用入口，不增加直连模型客户端。

优先批量解析同一段全局命令，优先复用既有单位决策结果，不默认让每个单位每回合各调用一次模型。批量规划中的逐单位条目应称为“单位决策记录”，不能伪称多个独立Agent。真正单位智能体按编组启用，并通过DSH原生服务与既有操作锁组织调用；并发能力未经验证不得开启。

## 4. 交互与界面

### 4.1 单位选择和快捷弹窗

1. 左键点击己方军标：高亮单位，打开锚定弹窗，显示名称、方别、兵种、当前任务及可用状态。
2. 弹窗提供常用按钮、行动下拉菜单、目标参数、单位自然语言输入，以及“当前命令／决策记录”页签。
3. 点击敌方军标通常仅查看已知信息；进入攻击目标选择时，将该单位作为目标。
4. 默认仅能指挥选定方。教学导演模式可控制双方，但必须显式切换、显示权限，不根据文字自行扩大控制范围。
5. 重叠军标提供单位列表选择，避免任意命中。缺失坐标的单位仍可从名单打开，不能虚构位置。
6. 首版不允许拖动军标直接改变部署；调整部署与回合移动是不同操作。

快捷动作由后端规则能力决定，不由前端硬编码全部开放：

| 动作 | 参数与交互 | 规则要求 |
| --- | --- | --- |
| 待命 | 直接形成草稿 | 单位可用，受全局限制约束 |
| 移动 | 地图选目的地；显示本轮预算和预计剩余 | 位移、边界、粮食与时钟约束 |
| 射击 | 选择敌方单位；显示已知射程与资源检查 | 射程、射界、弹药、停火和目标资格；未知不冒充通过 |
| 补给 | 显示已绑定补给来源与可核验条件 | 不自动创建补给点、不保证到货 |
| 破袭／修复／隐蔽／航空支援／接收 | 仅在对应演习动作集中显示为可执行 | 复用现有场景规则及其计算边界 |
| 决策记录／编辑／撤销 | 操作已有记录或待执行命令 | 不消耗战局时间，不改写已提交历史 |

### 4.2 地图选点

操作：选单位 → 选“移动” → 弹窗收起为提示 → 地图单击落点 → 预览 → 加入队列。

- 普通地图点击仍用于浏览；只有明确的选点状态才生成目标。阻止军标点击冒泡成为目的地点击，保留地图拖动和缩放。
- 目标位置由地图返回，统一采用现有经纬度字段契约；用户无需输入坐标。内部坐标顺序必须明确，不混用 `[lat, lng]` 与GeoJSON顺序。
- 预定路线用虚线，已执行轨迹保留现有样式；目的地有独立标记。命令预览图层与态势图层分离。
- 距离、机动上限和地形可通行性分别显示；范围圈只代表当前规则的几何预算，不代表真实道路或河流可通过。
- 首批仅支持单目的地、直线几何估计，不提供未经实现的自动道路寻路。
- 支持“仅下一回合”与“到达前持续”。持续目标每回合按当前规则分解为合法一步；不瞬移，不越过演习边界，截止或终局后停止。
- 持续任务受阻时保留目标与原因，默认暂停并允许用户调整，不反复消耗模型预算，也不擅自绕出新路线。
- `Esc` 取消当前选点并返回草稿；取消一段预览不推进回合、不删除其他单位命令。

### 4.3 三种统一输入入口

| 入口 | 默认范围 | 行为 |
| --- | --- | --- |
| 地图＋快捷菜单 | 当前单位 | 直接产生可校验的结构化草稿，无需模型解释明确操作 |
| 单位对话框 | 当前单位及所选地图目标 | DSH解析行动与补充要求；不再次追问已明确的坐标 |
| 全局指挥框 | 当前控制方 | 批量解析单位命令、战略偏好及全局限制 |

同一对话区域明确区分“咨询”与“下令”；“能不能撤退？”不得自动执行成撤退。自然语言解析结果始终先显示草稿，不因一句话完成就立即推进。

地图选点、单位选择和自然语言一起形成解析上下文。例如选中一营并标点后输入“前往选定位置，本回合优先保存兵力”；若补充文字与选点矛盾，应返回冲突供修改。缺少目标、同名单位、无法理解的条件不猜测执行。

全局输入例如“红方整体转入防御，已下达移动命令的单位继续行动，其余单位优先补给，不主动射击”。解析结果分别展示具体命令、战略偏好和禁止射击约束。没有防御或工事算法时，不能把“转入防御”直接变成额外战斗加成。

### 4.4 布局与可访问性

- 地图保持主要空间；桌面使用可折叠的单位指挥／命令队列侧面板，锚定弹窗只保留常用项。
- 窄屏转为底部面板，选择地图目标时收起遮挡；不叠多层模态窗口。
- 从单位名单可用键盘打开同一指挥功能；下拉菜单和输入有label，弹窗管理焦点，退出选点后焦点回到发起按钮。
- 颜色搭配文字与图标表达状态，不能只靠红绿。运行、取消、错误、未知和只读模式有明确文案。
- `MapView` 现有全图重绘会重建军标；选择状态和草稿必须由上层持有，用稳定ID恢复，不能因刷新或新快照丢失。

## 5. 命令与权威状态契约

```mermaid
flowchart LR
    UI[地图与菜单] --> D[统一命令草稿]
    NL[单位与全局自然语言] --> DSH[DSH解析与公开摘要]
    DSH --> D
    D --> V[领域校验与冲突处理]
    V --> Q[已确认命令队列]
    Q --> P[冻结初态及命令批次]
    P --> AI[DSH规划未接管单位]
    AI --> R[统一规则及守卫链]
    R --> C[持久化与原子提交]
    C --> VIEW[态势及逐单位执行回执]
```

### 5.1 单位身份与会话状态

新增 `command_state` 领域状态，含schema版本、单位注册表、控制方、命令修订号、当前队列、持续任务和执行回执引用。实际字段在阶段一冻结，不新建通用会话存储。

单位稳定ID独立于显示名称。旧对局先按现有名单建立映射；同名冲突不能自动合并，名称变更需要显式映射。固定演习优先将注册表放在会话附加状态中，避免改变已保存想定定义、初态摘要或规则版本。首版不新增拆编合编；退役单位保留历史，失能或不存在的单位命令不能自动转给另一单位。

`command_state` 复用 `session_store` 的检查点、JSON导出与导入。旧存档缺少此字段时按兼容模式读取；不能读取时保留原文件。新增控制字段不覆盖原有战场状态和模型配置。

### 5.2 命令字段与版本

| 字段组 | 最低内容 |
| --- | --- |
| 身份 | `command_id`、战局/epoch、单位ID、控制方、来源 |
| 行动 | 允许的动作、目的地或目标单位ID、必要场景参数 |
| 时效 | 生效回合、仅下一回合／持续到达、到达与停止条件 |
| 校验 | `expected_turn`、战局版本、命令修订号、规则版本、可执行性与原因 |
| 来源关联 | 用户原文或菜单动作、DSH运行及事件引用；纯手动命令不伪造DSH调用 |
| 结果 | 状态、实际行动、资源变化、偏差原因、关联决策与轨迹ID |

命令只引用已有实体和合法目标，不能携带覆盖 `war_state`、规则、人员基数或模型配置的任意字段。schema校验在客户端提示和服务端权威检查两处执行。

### 5.3 冲突与控制优先级

1. 模式、控制权限、程序规则、资源与时钟约束不能被自然语言覆盖。
2. “尽量保存兵力”等是软偏好；经用户确认的“禁止主动射击”等是硬限制。
3. 硬限制与具体命令冲突时阻止提交并显示冲突，不静默猜测优先级。
4. 用户已确认命令高于自主规划；模型仅规划未接管单位，不能重写手动目标。
5. 同一单位已有待执行命令时，新命令作为显式替换版本，保留原记录；持续任务的取消与替换同样可见。
6. 首版遵循现有演习“一单位一回合一个动作”；“先移动再射击”应拆成后续任务或明确标为当前不支持，不能暗增行动次数。

### 5.4 生命周期与原子性

命令状态：`draft → queued → executing → completed / blocked / cancelled / expired`。部分完成记录在实际行动与进度中；持续移动未到达时保持任务，并为下一回合生成候选一步。

回合启动冻结同一初态、队列版本、用户命令与全局限制。静态命令非法时在推进前拒绝；规则运行产生的受阻等结果按实际规则记录，不能伪造执行成功。双方命令按现有同时结算语义处理，调用先后不产生额外先手。

候选状态与命令结果通过既有时钟、名单、计数、射界和轨迹守卫后一起提交。失败、取消或必需轨迹落盘失败时不提交部分战局；保留用户队列供重试。通过命令批次ID与预期版本实现领域幂等，重复点击或网络重试不能执行两次。进程中断后的回执与检查点一致性需专门验收，不另建通用WAL或调度平台。

前端不能只依靠本地缓存；服务器持有已确认命令。版本过期返回冲突，刷新并提示重新校验，不能默默把旧目的地应用到另一回合。

## 6. 模式与交付边界

| 模式 | 指挥方式 | 结果与展示边界 |
| --- | --- | --- |
| 固定局部演习 | 首批完整接入菜单、选点、自然语言与命令队列 | 复用 `missions.advance`；保持合成教学假设及场景动作集合 |
| 普通开放推演 | 后续逐项接入可检查动作与命令履行审计 | 未实现确定性损失算法时仍标为模型估计；缺资源数据不当作零或无限 |
| 历史回放 | 查看可考指挥与来源 | 不在原回放直接执行替代命令；从明确快照另建开放分支 |

首批完整验收覆盖20个固定局部演习，不能据此宣称45个历史条目都具有完整战棋裁决。历史回放通过 `POST .../commands/open-branch` 从当前快照建立独立战局，保留来源ID及回合，不改写原回放；模型分支复用DSH，确定性分支复用纯函数规则，均保留原战局。

## 7. 逐单位决策与历史解释

所有单位每回合都有覆盖记录：人工接管、批量模型规划、独立DSH单位Agent、继续任务、默认待命、失能或决策缺失。移除固定6条/16条截断，使用逐单位引用和分页，不为覆盖率编造理由。

在结果结算前保存已提出行动及可公开的简短理由，之后关联实际执行与偏差。不能根据结算后的战果反推先前动机。总体意图不能重复填成每个单位的独立理由。

| 决策记录 | 必须区分的内容 |
| --- | --- |
| 任务与控制 | 收到的命令、全局限制、控制来源和单位身份 |
| 当时依据 | 传给规划者的当前观测、已知资源、资料来源或明确未知 |
| 候选与结果 | 计划行动、程序检查、实际变化、未完成原因 |
| 运行证据 | 命令ID、DSH会话/事件序号、规则与回合轨迹引用 |
| 历史性质 | 史料记载、用户干预、模型建议、程序结算分别标识 |

独立单位Agent只获得其配置的观察快照，不直接共享敌方私有命令。当前未实现战争迷雾，限制提示输入不等于已经获得真实情报模型。手动接管单位没有自主规划调用时，不生成假的Agent会话；公开摘要不是内部思维链，模型理由不是已经证明的因果解释。

现有位移归因与命令反事实继续保持只读。对照明确固定哪些条件、改变哪个命令；模型分支未控制的随机性照常披露，不产生虚假的胜率或贡献百分比。

## 8. 模块和接口草案

以下为已实现接口与文件。界面由 `CommandCenter.vue` 集中持有指挥草稿、队列及单位记录，避免弹窗、地图重绘各自维护一份命令；三个输入入口复用同一API。

| 模块 | 计划职责 |
| --- | --- |
| 扩展 `MapView.vue` | `unit-select`、目的地/目标选择事件、选择高亮与命令预览层 |
| `CommandCenter.vue` | 单位状态、动作菜单、单位/全局自然语言、约束、草稿、队列及完整回执分页 |
| `CommandCenter.vue`／`CausalPanel.vue` | 按单位与回合分页查看决策、执行差异和DSH引用；只读命令对照 |
| `gentactix/commands.py` | 标准库领域schema、身份、状态机、校验和执行适配；不写Agent框架 |
| `backend/command_routes.py` | 解析、确认和队列API；调用现有DSH、存档及锁 |
| 扩展原生项目插件 | 只读观察和命令检查，原生单位Agent适配与观测；复用既有注册入口 |

接口可统一使用 `/api/sessions/{id}/commands` 前缀：

| 操作 | 请求关键内容 | 返回／副作用 |
| --- | --- | --- |
| `GET .../commands` | 战局ID | 控制能力、单位映射、队列、持续任务及修订号 |
| `POST .../commands/resolve` | 文本、咨询/下令、已选单位和地图目标、预期版本 | DSH解析的草稿、歧义和检查结果；不推进、不确认命令 |
| `PUT .../commands` | 明确命令或编辑结果、全局限制、预期修订号 | 校验后保存队列；无模型的菜单命令同样走这里 |
| `DELETE .../commands/{command_id}` | 预期修订号 | 取消未执行命令或持续任务，不删除历史回执 |
| 扩展 `POST .../next` | 命令批次、预期回合与版本 | 统一规划和结算，成功后返回实际命令结果 |
| 单位决策查询 | 单位ID、回合范围、分页 | 完整记录与既有DSH轨迹引用，不能固定条数截断 |

纯咨询继续使用已有问答路径；无需新建聊天系统。结构化返回、取消、错误门控与模型预算均复用 `harness_engine`。API版本为命令领域schema v1。`next` 增加 `batch_id`、`expected_turn`、`revision`、`world_version`；启用命令队列的会话必须提供完整版本，重复批次不再次扣减。没有命令状态的旧会话继续接受 `next(instruction)`。

每阶段更新本文件状态、实际变更与验证证据；后续变更若缩减已确认交互或改变规则边界，需明确记录，不能悄悄以降级替代完成。

## 10. 验收清单

### 10.1 规则、数据和API

- 单位ID在刷新、导出导入与恢复后稳定；同名、失能、退役与缺失位置不误指挥。
- 移动目标、控制方、超距、弹药、边界、场景专属动作和停火限制由服务端检查；缺失数据保持未知。
- 用户命令不被自主规划覆盖；全局限制冲突可见；同单位重复命令有明确替换记录。
- 单回合动作数、持续移动、受阻暂停、终局停止和时钟符合规则，不发生瞬移。
- 名单、人员、装备、初始基数和库存连续；失败、取消及重试不产生部分提交或双重扣减。
- 旧存档不强制改写，队列和持续任务可恢复；配置与既有对局在隔离验收前后不变。

### 10.2 浏览器与桌面

- 普通浏览、单位选择、攻击选目标、移动选点互不误触；取消选点不改变战局。
- 弹窗不遮挡落点，地图重绘不丢选中单位与草稿；范围与路线的几何估计标签清楚。
- 单位菜单、单位对话、全局输入产生等价命令；队列编辑、撤销及版本冲突路径可操作。
- 宽窄屏、键盘操作、焦点恢复、未知值、无网络瓦片、服务断开、模型失败和运行取消均有可见状态。

### 10.3 DSH与真实推演

- 注册工具实际出现在原生请求与事件中，返回的是当前冻结快照；仅有UI名称或配置项不算接入。
- 使用真实DSH验证指挥解析、单位规划、在途取消、恢复和所启用的原生分支；固定响应仅用于接口和UI验证。
- 单位Agent声明必须对应真实原生身份与事件；批量记录不能冒充多个独立Agent。
- 所有单位有覆盖记录或明确缺失标记，手动命令有执行回执；无历史来源时不冒充史实命令。
- 相同初态的命令干预能产生合理且可解释的差异；原始反事实不覆盖主战局。
- 保留真实失败、耗时、调用数和未覆盖项；不得用降低思考强度换取通过，也不能把软件通过等同历史有效性。

相关回归沿用 `verify_*.py` 命名，新增命令核心、API与浏览器契约检查。按改动运行现有使命、守恒、时钟、DSH、插件、配置及发布边界用例；跨模块变更遵循根目录完整回归要求。提示或状态管线变化另运行 `measure_turn_degradation.py`。前端执行 `npm --prefix frontend run typecheck` 和 `npm --prefix frontend run build`。

## 13. 实际前端状态与操作约定

`App.vue` 持有地图选中单位、选点模式与预览；`CommandCenter.vue` 按稳定ID保留草稿，`MapView.vue` 只发选择事件。单击军标打开指挥面板，同点军标先列出单位；无坐标及退役单位可从名单进入记录。移动选点时收起面板，Esc返回草稿，焦点回到选点按钮。窄屏使用底部面板；预定线、机动圈、实际轨迹分别展示，距离不解释成道路或通行保证。

已确认命令存入现有 `session_store`。自然语言解释先形成只读草稿，只有确认才进入队列；过期解释和被修改的解释来源不被采纳。咨询继续走已有问答接口。持续任务保留同一命令ID，受阻暂停，失能或退役终止，终局停止；重名新单位不能继承退役任务。

单位Agent只对启用且没有人工接管的单位调用。插件经原生 `ctx.agents.create/resume` 建立独立上下文，不复制总参谋长或引擎提示；每次重新注入权威观察与全局限制。恢复失败明确报错，用户可关闭该单位Agent，或明确选择重建会话记忆；原日志保留。取消复用原生 `Agent.cancel`，不另建调度器、聊天客户端或会话库。

完整验收与已知边界见[本地战棋指挥验收](战棋指挥验收-2026-10-24.md)。合成教学规则的通过不证明历史战损或道路通行有效；普通开放场景除位置命令外的损耗仍是模型估计。
