## 依赖修复

前端完整 `npm audit`（包含构建依赖）从 **8 个中风险节点降为 0**，Worker 审计也为 0。
这些节点来自同一条依赖链：`@electron/get@3.1.0 → global-agent@3 → roarr → sprintf-js`。
`sprintf-js` 的[精度拒绝服务公告](https://github.com/advisories/GHSA-hp3w-g68c-fv3c)当时没有修复版本。
采用范围限定的 npm override，将该下载器的 `global-agent` 固定为 `4.1.3`；上游从
[4.1.0 移除了 roarr](https://github.com/gajus/global-agent/releases/tag/v4.1.0)，实际移除漏洞链，未隐藏审计或降级 Electron。

兼容验证覆盖：干净 `npm ci`、HTTP/HTTPS 代理下载、NO_PROXY、错误校验和拒绝、不可信 TLS 证书拒绝、TypeScript 检查及实际 Linux 打包。测试使用临时本机代理与证书，不改系统代理或放宽 TLS 校验。

## 测试发现与修复

- **异步轨迹落盘**：DSH完成通知早于JSONL缓冲写入，立即读取曾只找到6/9个事件。核验现在最多等待2秒，匹配序号及类型；缺失仍返回partial，完整行损坏返回corrupt，不补造记录。
- **失能单位影响几何**：HP归零后仍留在名单，旧逻辑把0当作默认1，继续参与封锁与包围。`geo-4`排除HP≤0单位的几何影响；保留世界状态与战损记录，隐藏其当前火力圈/射界，桌面显示灰色“已失能”标记。
- **恢复后控制栏不一致**：已保存上甘岭战局恢复时，侧栏仍显示长平与30分钟默认值。API快照补充会话设置，恢复时同步想定、跨度、裁决、RAG和智能体配置。
- **系统安装目录不可写**：`.deb`安装到`/opt`后，密文配置自动使用用户数据目录的`project/`，保留显式项目根目录覆盖。

第5回合起存在 `hp_zero_alive` 提示，最终两个红方单位HP为0，仍保留供核对；修复不删除这些提示或历史单位。**HP不是人员数**。本轮模型没有给出人员/装备计数、地形要素和补给节点，不能据此验证这些图层的完整生成或真实战损率。本轮原生领域工具调用为0，验证的是Native会话与轨迹持续性，不是模型主动调用工具的效果。既有工具与丰富图层回归仍单独执行。

## Ubuntu 交付与回归

提供 AppImage、便携tar.gz、Ubuntu amd64 `.deb`。`.deb`包含应用菜单、图标及安装/卸载脚本；AppImage可双击运行，也提供免sudo的用户菜单/桌面安装脚本。配置密文、解密密钥、战局和QA原始日志不进入安装包。

离线、Worker与Docker：28/28任务通过。桌面SDK与战场展示套件共150项，149通过、1项Folium检查在DSH环境中跳过；该项由`.venv`的17项战场展示测试覆盖。另有下载代理、Electron启动边界、安装目录权限、轨迹并发写入、失能单位几何/展示与恢复配置回归。

Ubuntu菜单文件与48/256/512像素图标随`.deb`提供；本机实际配置的是无需sudo的用户级菜单及可信桌面图标。系统级`.deb`安装需要管理员权限，本轮不冒充已在宿主执行过该安装。安装包提取与菜单规范检查、包内程序启动分别验证。

用户级安装后另发现旧 GTK 缓存导致图标名查找失败。安装脚本现刷新缓存，并在菜单项中使用图标绝对路径；重装入口后 GTK 加载及 Ubuntu 左侧任务栏图标显示均已验证。此修复位于源码安装工具，不改变已构建的应用二进制。

可复现命令见[QA工具说明](../tools/qa/README.md)，安装方式见[桌面使用说明](桌面启动与配置.md)。原始证据位于本机 `.cache/qa/soak-20-20261022/`。结论限于这一个四单位局部想定与列出的测试；不代表九场战役、超大规模、多日战役或真实历史伤亡均已验证。
