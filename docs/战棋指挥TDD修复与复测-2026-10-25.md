# 战棋指挥 TDD 修复与复测

发布跟进：用户随后授权更新安装程序与GitHub；本报告中的源码改进已纳入[3.3.0安装包](releases/v3.3.0.md)。以下“未发布”记录指TDD修复完成时的状态。

本轮按“先复现失败，再修复，再回归”完成上轮审计的七项问题。仅更新本地源码及测试，未上传 GitHub，未替换已安装的 3.2.1 程序。

## 问题与实现

| 问题 | 修复后的行为 | 主要证据 |
| --- | --- | --- |
| 修改输入或解析失败后，旧移动草稿仍可确认 | 草稿绑定会话、单位、回合、规则观察、文本、范围、选点及控制设置；输入改变即失效，迟到响应丢弃。预览显示解析原文、目的地／目标及持续方式 | 浏览器故障组 1、2 |
| 已知版本冲突后一直复用旧批次 | API 错误保留 HTTP 状态。409 明确拒绝时释放旧批次并刷新；网络失联等结果未知时保留原幂等键，刷新也不清除 | 浏览器故障组 3、4；第二种测试先让服务端提交再丢弃响应，重试仍只有一轮 |
| 失能／退役单位旧任务阻断整轮 | `prepare` 将任务区分为可执行、受阻、终止；不为失能／缺席者注入待命。成功提交时归档一次并记录原命令 ID，失败或取消时不改原队列 | 新增后端完整执行链测试；覆盖已暂停后失能和写盘失败 |
| 无坐标单位可下待命，却不能完成推演 | 普通开放场景的能力表仅允许待命；未知位置保持未知，禁止待命过程中凭空产生或丢失坐标。回执明确标为位置未知，其他效果仍是模型估计 | 后端未知位置两项测试 |
| 对照结果错挂到新单位／回合 | 结果绑定单位与观察版本，标注 `T+回合 · 单位`；选择或态势改变即清除，迟到响应不落入新上下文 | 浏览器故障组 5 |
| 前端没有 JSON 导入入口 | 启动页、工作台均可选择文件，服务端预览后显式确认。预览不写盘，确认再次校验；内存和磁盘 ID 冲突均拒绝覆盖。兼容旧导出加原快照；提示原生 DSH 日志不在 JSON 中 | 后端导入测试、浏览器故障组 7、Electron 实测 |
| 控制方切换被旧 Agent／命令卡住 | 列出超出新控制范围的命令和 Agent；用户确认才撤销／停用，取消保留原状。同范围记录保留，后端权限守卫不放宽 | 后端权限与精确清理测试、浏览器故障组 6 |

普通浏览器复测还发现草稿确认时过早清除预览的时序问题，已改为保存成功后更新策略与清除草稿。原有单位／全局指挥闭环重新通过。

DSH 继续使用现有 Native 工具模式、原生单位会话与事件、恢复和 `Agent.cancel`。没有新增智能体调度器或聊天传输层；本轮仅让终止任务退出现有规划入口。真实测试仍为高推理强度、65,536 token 引擎预算。

## TDD 与验证结果

- `verify_command_recovery.py`：修复前保存了失败日志，修复后 **10/10**；包含子用例，不把故障注入算作真实模型证据。
- `command_recovery_browser.js`：修改 UI 前 **7/7 组失败**，修复后 **7/7 组通过**，无未捕获异常。
- `verify_all.py --with-worker`：**36/36 组**，共 **322 个 unittest 用例、0 跳过**。包含 Streamlit、后端、20 个固定演习账本、检查点、轨迹、提示退化及 Worker 构建。
- 原有命令浏览器 **17 项检查**通过；通用界面、故障注入、固定演习三个浏览器套件通过。检查了 1530×980、390×844 视口及实际截图。
- Electron 原生菜单快捷键、`file:` 渲染、同回合导入后队列刷新、导入后推进及 **6 个单位回执**通过；渲染层没有 Node `require/process`。
- 真实 DSH **8/8 项**通过，用时 **139.29 秒**：自然语言与地图目标、两个独立原生单位及观察工具、重复批次、重启恢复、在途取消及重试、显式会话重建、终局、普通开放移动。该测试包含四轮固定演习和一次普通开放推进，不能外推为全部战役逐场验收。

原始证据在 `.cache/qa/tdd-20261025/`：`backend-red.log`、`backend-green.log`、`browser-red.log`、`browser-green.log`、`regression-results.json`、`browser-results.json`、`live/result.json`。启动服务未就绪导致的一次连接失败单独保留为 `browser-startup-race.log`，未算作产品通过证据。

## 依赖与构建复核

本轮 `npm audit` 另外发现 Worker 的 `wrangler → miniflare → undici@7.29.1` 链存在 1 高、2 中风险节点。按上游公告的修复版本，对当前 Miniflare 版本限定覆盖为 `undici@7.30.1`，保留 Wrangler 版本；锁文件同步更新。依据：[EventSource 内存问题](https://github.com/nodejs/undici/security/advisories/GHSA-4qv8-2p9j-2685)、[完整性检查问题](https://github.com/nodejs/undici/security/advisories/GHSA-f72v-6w45-q472)、[内容编码错误处理](https://github.com/nodejs/undici/security/advisories/GHSA-xjj6-f33q-929c)。上游依赖更新后应移除该限定覆盖并重新审计。

修复后 Worker、前端审计均为 **0**。前端类型检查和生产构建通过；Worker 类型检查、`--dry-run --containers-rollout none` 本地打包及 `tools/qa/worker_runtime.mjs` 的真实本地 HTTP 请求／响应通过。未部署 Cloudflare，未生成发布安装包；一次误触发的本地容器构建已取消，不计为通过。

## 数据保留与能力边界

测试前后比对原配置、密文、Vault 密钥、角色索引、战局、轨迹、DSH 目录及安装入口，共 **2273 个文件**内容和权限一致，受保护目录没有新增文件，原 **6 个对局**保留。原始测试目录含模型输出及本机路径，不应随源码上传。

普通开放场景当前可核验的单位命令仍限于 `hold/move`，其余损耗与效果仍由模型估计。几何预览不证明道路通行、地形遮挡或真实射界；固定演习通过不证明历史伤亡准确。原生日志缺失会明确失败，JSON 导入不会补造 DSH 会话记忆。
