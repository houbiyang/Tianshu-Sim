# 可重放局部推演实施约定

本轮对象为20个抗日战争资料场景。保留原有叙事推演；新增可选的“固定局部教学初态”，与史实复原明确区分。

## 流程与状态

启动页选择开放推演或历史回放；选择固定局部初态时显示版本、教学假设和程序目标。固定初态不调用模型生成兵员或库存。下一轮由模型提出命令，程序结算移动、消耗、交战与目标，提交前验证；失败不改变战局。目标终止后不能继续推进。

`LaunchScreen → App → /api/sessions`传递`simulation_mode`和`mission_id`；后端会话保存这些选项，快照恢复时回填。`/api/missions`提供只读目录，`/api/sessions/{id}/next`接受可选用户指令。`war_state.mission`保存规则版本、初态摘要、目标、账本与终局。历史回放不作为反事实验收模式。

## 计算边界

纯标准库使命模块是可选的教学规则层，不修改默认关闭的几何裁决开关。固定初态使用公开地名附近的合成局部坐标、代表性编组与教学库存，不宣称已核定历史部署。按任务类型分别处理据点争夺、迟滞撤离、交通破袭与修复、组织隐蔽存续、航空遮断及接收。统一账本使用人数、装备件数、粮弹工作单位，禁止以HP换算人员。

## 界面与验证

启动配置保留键盘可达的原生select和label；在工作台展示规则状态、目标进度、实际消耗及终局。回合选项统一“天”，兼容旧“日”存档。模型模式、教学假设与部分能力不得用成功标签掩盖。

验证包括：模式与检索冲突、重放一致、命令差异、无补给行动受限、人员装备连续、目标成功/失败/截止、非法命令原子拒收、保存恢复、桌面宽窄屏。逐场真实模型验收使用隔离目录与当前模型配置，保留high及65,536输出预算，不覆盖既有战局。测试通过只证明定义的教学规则与软件行为，不能替代史实参数校准。

## 当前局部规则

| 类型 | 行动与结算 | 红方程序目标 |
|---|---|---|
| 据点争夺 | 有效射程内同时结算；被打掉的单位仍留在账本 | 目标区有红方且无可用蓝方，连续两轮 |
| 迟滞 | 移动、交火、库存消耗；后方出口独立检测 | 第4轮仍有至少两个红方编组，蓝方未进入后方出口 |
| 突围 | 粮食不足时移动预算减半 | 至少两个红方编组到达出口，连续两轮 |
| 交通破袭 | 目标600米内破袭−40、修复+25；完好度≤20时阻断蓝方到货 | 完好度≤20连续两轮 |
| 组织存续 | 每轮组织值−15，每个红方隐蔽编组补偿+5；隐蔽减少本轮受击 | 截止时组织值≥50且有可用人员 |
| 航空遮断 | 支援消耗3弹药工作单位，敌方本轮到货率减半 | 控制目标区两轮 |
| 停火接收 | 第2轮之后禁火；窗口内抵近目标可接收 | 红方完成接收并连续确认两轮 |

全部使用合成的6个编组、每组100人和4件支援装备；30分钟/轮，最多4轮。不同战役绑定相应类型，**不意味着这些人数、地点、时钟和系数来自史实**。航空支援是抽象资源动作，不是飞行与制空权解算；组织存续值不是地下工事结构模型。所有类型共享的交火系数不经过历史伤亡拟合，不提供伤亡预测精度保证。

补给点有限库存按固定编组顺序分配（显式优先级）；待命正常到货2包、主动补给8包，路线切断或库存耗尽则为0。每包同时包含1单位粮食和1单位弹药；移动耗粮4、其他行动耗粮2，射击/支援耗弹3。粮食不足4时机动减半；弹药不足3时射击拒收；缺粮产生单列非战斗减员。它证明库存会约束行动，不代表真实运输车辆、道路容量或弹种消耗。

`missions.advance`只接收命令，返回新状态；非法命令整轮拒收。任意编组消失、初始基数/固定性能改变、人员或装备账不平、越界、无弹开火，都会拒绝。相同初态、规则版本、命令序列可离线重放；JSON顺序不决定谁先射击。共同守卫的`carried_forward`只作展示标记，重放比较排除此标记，其余状态逐项核对。

## 验收入口

```bash
.venv/bin/python verify_missions.py
/home/spikebai/anaconda3/envs/wargame/bin/python verify_mission_backend.py
/home/spikebai/anaconda3/envs/wargame/bin/python tools/accept_missions.py --workers 4
```

真实验收使用现有加密模型配置；每场独立DSH工作目录、会话和轨迹，最多4回合。`--ids AJ01-local-v1`可只跑一场。失败记录归档后可再次运行从已提交检查点续验；每个真实回合同时离线重算、执行红方待命对照、核验DSH事件及存档恢复。补给耗尽分支单独记录为确定性干预，不能冒称模型发现了补给规律。

程序胜负不等于验收成功：红方未达目标可以是有效终局；时钟、账本、轨迹、重放或对照失效才属于软件验收失败。推演策略质量需另外人工审阅。真实结果保存在`.cache/mission-acceptance/`，不得将该目录的原始模型日志或本机设置上传。

尚未覆盖：历史真实编制初态、道路/河流/DEM配准、视线遮挡、战争迷雾、通信链、完整工事、跨战役态势继承、统计标定和对所有胜负条件的历史学验证。长征和抗美援朝资料可继续使用原有模型生成流程；本轮固定局部初态仅覆盖20个抗日战争资料场景。
