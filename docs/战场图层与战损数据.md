# 战场图层与人员装备战损

Vue桌面界面的地图上方可独立开关地形要素、射界、火力射程和补给线，并可切换地形底图。地图下方新增“态势与战损”页。Streamlit入口提供同口径的Folium图层和“地形、火力与人员装备战损”折叠表。

## 地形与火力

- 地形底图沿用Esri World Topo，仍依赖网络。`current_terrain`显示战区地形标签；启用裁决时额外显示实际使用的机动拖慢系数与来源。
- `terrain_features`绘制已录入的山脊、河流、道路、林地、城市与工事，可用点、线或面。没有坐标就不补造地形。标注高程来自记录，不是现场查询的DEM。
- 单位`attack_range`和`min_attack_range`单位为米，分别绘制最大、最小射程边界。显式射程优先，缺值时使用已有兵种工作估计并显示虚线；不支持的兵种保持空缺。显示层接受0—500公里内的有效正最大射程，越界不绘制。
- `fire_sector.bearing_deg`从正北顺时针，`arc_deg`为水平射界角，取0—360度之间；未知方向不画扇区，不根据敌军位置猜方向。扇区按球面距离生成，扣除最小射程区域。完整360度覆盖用射程圈表达。
- 射程圈与交战示意图形均不代表杀伤半径、命中率或占领土地。当前未接入数字高程、坡度、视线遮挡或弹道解算；地形底图不参与确定性遮挡裁决。

## 补给节点与路线

`supply_nodes`记录节点ID、阵营、坐标与来源。`supply_routes`记录途经点、受供单位、通行状态与来源。绿线表示战局记录通行，红线表示记录受阻或几何截断，黄色表示受威胁或未核实；提示框标明依据。

同一单位优先采用已记录路线，其次是指定补给节点的直连估计，最后才采用裁决内核的几何后方直线。估计均为虚线；几何后方不是实际仓库，没有道路寻径、运输能力、运量、桥梁通行或空中遮断结算。未开启裁决且未提供节点/路线时，不凭空生成补给线。

## 计数契约与比例

人员使用`personnel`，装备使用`equipment`，与抽象`hp`分开。结构示例中的数字仅说明字段：

```json
{
  "personnel": {
    "committed": 1000, "current": 900,
    "casualties": 80, "noncombat_losses": 20,
    "source": "推演估计，非历史实测"
  },
  "equipment": [
    {"name": "榴弹炮", "unit": "门", "committed": 12,
     "operational": 9, "damaged": 1, "destroyed": 2,
     "source": "推演估计，非历史实测"}
  ],
  "attack_range": 8000, "min_attack_range": 1000,
  "fire_sector": {"bearing_deg": 90, "arc_deg": 80}
}
```

人员战斗减员率=`casualties / committed`，非战斗减员率=`noncombat_losses / committed`。装备永久损失率=`destroyed / committed`，可用率=`operational / committed`；`damaged`是当前待修量，与累计永久损失分开。各分类须避免重复计数，累计投入随补充增加，不在下一回合清零。各类装备按名称和计量单位分别汇总。

计数需为非负整数。缺字段、分母为零或分项超过累计投入时显示“未记录”或异常说明，不产生0%或强制截断后的比例。双方汇总采用完整记录的加权总量，并显示覆盖单位数；计数不全时不冒充全军交换比。数据由史料/模型战局提供，本次没有新增确定性伤亡算法。

## 跨回合与旧战局

候选战局提交前，保留漏写的地形、节点、路线与同名单位的嵌套计数；装备类别遗漏时保留已有记录。明确退场的单位进入`loss_records`，保存最后计数和时间，不根据退场自动补成100%伤亡。后续可提交退场单位的最终人员、装备明细。重新出现的同名同方单位接回原记录，避免重复计数；跨战役同名单位不共享数据。

当前编组可用人数只统计仍在编组内、计数完整的单位；累计损失可包含退场单位的最后记录，界面明确标注其状态。导出的`war_state`包含这些记录。新初始化从新战局开始，不继承上一局账本。

同方同名单位在当前编组和退场账本间只计一次；退场状态由记录所属容器决定，不能通过状态文字改成现役。装备漏写计量单位时，仅在同名旧装备唯一时接回原计量单位，防止重复计数。后续回合人员或装备的累计投入若小于既有记录，直接拒收该回合并保留原战局，不以重置后的分母生成比例。

旧战局无需添加新字段即可继续显示原有单位。旧HP不会转换为人数；旧兵种射程仍可作标注估计。代码更新后需重启后端并刷新前端加载新快照字段；新局会通过提示词请求上述数据，但资料不足仍保留未知。

## 验证

运行`.venv/bin/python verify_battlefield.py`检查数据、球面射界、补给优先级、统计分账和退场保留。运行`.venv/bin/python verify_all.py`执行全量离线检查。在`wargame`环境运行`python verify_desktop_backend.py`覆盖初始化、部分更新、退场与导出链路。前端在`frontend/`运行`npm run typecheck`和`npm run build`。
