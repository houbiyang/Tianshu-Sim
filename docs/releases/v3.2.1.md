# GenTactix-DSH 3.2.1

发布日期：2026-10-24

## 故障现象与原因

旧版桌面程序保存的 DeepSeek 官方地址为 `https://api.deepseek.com/v1`。DSH 使用 Anthropic Messages 协议，而 DeepSeek 对应的兼容入口是 `https://api.deepseek.com/anthropic`，因此 Harness 初始化请求命中了错误路由并返回 HTTP 404。模型调用没有成功完成，界面最终显示：

```text
harness 未完成（finish_reason=error），本次输出已拒收
```

此外，连接测试完成后前端没有重新获取健康状态，即使后端状态已经改变，界面仍可能继续显示测试前的 `harness_started=false`。

## 改进内容

### DeepSeek 地址兼容

- DeepSeek 预设地址改为 `https://api.deepseek.com/anthropic`，模型保持为 `deepseek-flash`。
- 新增旧配置迁移：读取配置时，仅将 DeepSeek 官方域名的根地址和 `/v1` 地址迁移到 `/anthropic`。
- 自定义代理、vLLM 地址和其他兼容服务不参与迁移，避免误改用户部署。
- 迁移发生在配置校验和 Harness 环境初始化阶段，原有加密 API Key、输出预算和角色策略均保留。

### 错误诊断

- HTTP 404 错误现在明确说明 DSH 需要 Messages 路由，并给出 DeepSeek 官方 `/anthropic` 地址。
- 鉴权错误同时识别 DSH 的 `AUTH` 和旧的 `AUTHENTICATION` 分类。
- 错误响应保持脱敏，不返回 API Key 或原始服务端敏感信息。

### 前端状态刷新

- 模型连接测试无论成功或失败，都会通知父组件重新获取健康状态。
- 成功调用后可以立即看到 `harness_started=true`，不再保留测试前的陈旧状态。

### 构建与版本

- 应用版本由 3.2.0 更新为 3.2.1，后端 OpenAPI 元数据、Electron 包版本和锁文件保持一致。
- 构建脚本设置 `PYTHONNOUSERSITE=1` 并移除 `PYTHONPATH`，防止用户级 Python 包污染冻结后端。
- 使用 Python 3.10 独立打包环境重新冻结后端。
- 重新同步并封装 `deepseek-harness-sdk==0.2.1rc2` 和 `deepseek-harness-runtime-bin==0.2.1rc2`。
- 本地打包环境加入 `.gitignore`，避免依赖目录被误提交。

### 实际模型连接测试

测试使用与 Electron 桌面程序相同的用户数据、DSH Home、Workspace、会话和轨迹目录环境。应用通过自身的 `/api/llm/test` 接口发起一次最小连接请求：

```json
{
  "ok": true,
  "model": "deepseek-flash",
  "transport": "DSH",
  "finish_reason": "completed"
}
```

请求返回 HTTP 200。随后的健康检查确认：

```text
harness_started=true
runtime.enabled=true
runtime.connected=true
runtime.plugin=gentactix-runtime
runtime.mode=native
```

DSH 已加载 `get_observation`、`retrieve_history`、`evaluate_action`、`inspect_trajectory` 和 `evaluate_counterfactual` 工具。测试完成后临时后端已正常关闭，没有遗留进程。

## 安全说明

- 文档、源代码、构建产物和测试输出均未记录 API Key 或系统密码。
- API Key 只以加密形式保存在用户配置目录中，接口仅暴露“是否已配置”的布尔状态。
- 如果密钥曾通过聊天、日志或其他非安全渠道发送，应立即在服务商控制台撤销并重新生成。
