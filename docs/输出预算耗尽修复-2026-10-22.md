# DSH 输出预算耗尽：定位与本机验收

本轮为本地修复，不推送或发布 GitHub。原战局未用于自动测试推进。

**后续配置变更：** 用户明确要求保持高推理强度，并将输出预算提高到64K。本机全局与裁决角色上限现为65,536，裁决强度为`high`；新建配置的裁决默认值同步调整。预算建议按钮仅调整上限，保留用户所选强度，错误提示不再建议降低强度。以下低强度配置及耗时为变更前的历史验收记录，不代表当前配置性能。

此次配置变更通过60项配置、Harness和插件回归；浏览器验证64K预算保存及高强度、继承默认选项均不被建议按钮改写。配置API回读确认生效，5个战局状态保持一致；未为此次设置变更发起新的模型推演。

## 失败原因

23 单位想定在第二回合出现 `finish_reason=max-tokens`。DSH 原始请求记录显示输出上限为 16,384、推理强度为 `high`；界面当时显示的“服务默认”实际继承了 DSH 请求配置。失败调用约 138 秒，输出恰为 16,384 token。流式记录中，推理阶段约 119 秒，最终正文阶段约 13 秒；最终 JSON 不完整。

这是单次生成的输出预算耗尽，并非连接失败。推理和最终正文共用预算；上下文容量 262,144 与输出上限不是同一参数。全局和角色上限取较小值，仅修改全局上限仍可能被已保存的角色配置限制。

失败输出未提交。用户随后一次重试已完成第二回合，修复验证以其失败前状态及失败时的原生会话历史建立独立副本，不覆盖用户后来已完成的结果。

## 修改

- 新配置的全局默认上限为 32,768，裁决角色默认采用低推理强度。显式保存的强度（包括继承默认）仍予以尊重，不静默迁移已有配置。
- 本机现有加密配置已通过配置 API 同步调整全局与裁决角色上限为 32,768、裁决强度为 `low`；密钥及其他角色配置保留。
- 模型配置界面显示裁决有效上限，明确“继承 DSH 默认”的含义。建议按钮同时填写两个上限和裁决强度，点击保存才生效。
- 报错显示已消耗的输出 token，说明两个上限及推理预算的关系。仍严格拒收非 `completed` 输出，不拼接截断 JSON，也不自动提交失败候选。

## 验收结果

使用当前实际 DSH/vLLM 服务，在独立 DSH 数据目录恢复失败时的会话前缀及第一回合状态，连续推进两次：

| 验收 | 第二回合 | 第三回合 |
|---|---:|---:|
| HTTP / DSH 结束原因 | 200 / completed | 200 / completed |
| 耗时 | 71.72 秒 | 111.94 秒 |
| 输出 token | 7,328 | 13,515 |
| 23 单位名单保留 | 通过 | 通过 |
| 检查点恢复与内存状态一致 | 通过 | 通过 |

原生 `request/header` 记录确认新请求为 `maxTokens=32768`、`reasoningEffort=low`。测试复用会话历史，但未调用生产战局推进接口。

59 项模型配置、Harness、插件回归通过；另 47 项桌面、部署、时钟及发布边界回归通过。最终错误提示调整后，17 项配置测试再次通过。离线入口 24/24 任务通过，桌面 SDK 用例由上述独立环境补充验证。前端类型检查和构建通过。

浏览器使用固定响应验证建议只填写草稿、保存同时提交两个预算、保留空白密钥语义、有效上限取较小值；1440 与 390 像素视口检查通过。浏览器夹具结果不替代真实模型测试。

Linux AppImage、压缩包及 deb 已本地重建；Ubuntu 菜单和桌面启动入口已更新。本机后端及桌面程序已重启，5 个战局的状态、回合数、战报、轨迹和失败记录逐项一致，运行后端源码版本与磁盘一致。没有执行上传或发布。

证据位于本机 `.cache/qa/token-budget-20261022/`，包含脱敏汇总、测试日志及隔离轨迹；该目录不发布。两次通过不保证任意规模想定均不会耗尽预算，也不代表回合耗时恒定或战损预测已得到历史验证。
