# 功能验收与有效性分析

本文保留战场展示与锚点轮次的验收记录。后续新增的原生DSH插件、取消、因果与反事实结果，见[最新架构与验收说明](因果分析与DSH插件架构.md)和[当前测试汇总](../TESTING.md)。

验收日期：2026-10-21。结论：**展示、基础状态保护与模型调用链有效，但当前仍不能作为时间和战损均受严格约束的战役仿真器。** 自动化脚本通过不等于历史真实性或全部推演语义正确。

### 补入锚点后的新源码实测

另起全新Python进程加载本次源码，通过真实DSH/vLLM完成上甘岭初始化与下一回合，未改动8700的内存会话。初始化47.77秒、下一回合67.03秒；两阶段均返回200且测试脚本正常退出。两支守备连声明`node_name`，分别落在597.9高地、537.7高地北山参考坐标；中心距597.9参考约0.96公里。12个单位均保留，全部兵种能被近现代分类器识别，无位移越界或名单回填。

该受控样本指定蓝方一个突击连在守军200—300米处出发，15分钟、地形系数2.2下初始2个、下一回合4个地面单位被判定可接触。它说明该系数下存在可接触部署，不证明默认生成的所有战役均能及时接敌。明确钟点`04:00→04:15`在本样本正确；此前模糊“拂晓前”样本的时间跳跃仍是未修复失败，不能用一次成功抵消。

## 有效性对照

| 能力 | 已验证有效的部分 | 实际限制 |
|---|---|---|
| 地形 | 地形系数从1改为2，可机动距离从0.94公里降至0.47公里 | 单独添加河流图形不改变裁决；无DEM遮挡、道路或过河计算 |
| 射界与远程火力 | 最大/最小射程与球面扇区可绘制，未知方向不猜测 | 没有确定性开火、命中和伤亡结算；`can_contact`是机动可接触，不是远程能否开火 |
| 补给 | 节点、记录路线、直线估计和几何截断可显示并区分来源 | 把记录路线标成cut不改变内核指纹；没有运量、库存消耗或道路寻径 |
| 人员装备 | 独立分母、加权汇总、未知值与退场保留有效 | 比例只是录入/模型计数的统计，不是独立验证的历史损失或毁伤模型 |
| 状态与工具 | 漏字段回填、候选提交失败保护、只读试算与真实工具闭环有效 | 单位仍为抽象编组，不是逐名士兵或逐件装备的完整生命周期智能体 |
| 实时情报与恢复 | 导出当前状态有效 | 实时情报开关仍是叙事提示；无联网情报采集。内存会话不等于重启后恢复，暂无完整导入恢复界面 |

对照证据：[effectiveness.json](../.cache/qa/acceptance-20261021/effectiveness.json)。例如敌距2.76公里、炮兵射程12公里，`can_contact`仍为false，因为它按15分钟的机动距离判断，不能把这个字段读成“炮兵无法打到”。

## 本轮发现并处理的问题

1. **重复统计：** 当前编组与退场记录同方同名时曾重复计数，已去重并提示。
2. **退场状态：** 模型把退场记录的状态文字写成“当前编组”时，曾计入可用人数；现按记录容器判定。
3. **分母重置：** 人员或装备累计投入下降曾被接收，导致比例失真；现拒收回合，后端回归验证状态、回合、战报与裁决均不变。
4. **装备单位遗漏：** 漏写“门/辆”等计量单位可能产生重复类别；现唯一匹配时补回旧单位。
5. **问答观测：** 非持久会话的问答遗漏observer传递，现已补齐完成状态与耗时观测。
6. **能力解释：** 原问答把战损归因于尚未实现的火力/工事修正，首次补充边界后仍混合不同统计类别。已向两套引擎的复盘、问答加入明确能力边界与逐项公式；真实复验正确返回8.00%、2.00%、16.67%、8.33%，且明确没有确定性伤亡和DEM算法。提示词约束不是所有未来回答的正确性保证，面板程序计算仍是口径依据。
7. **朝鲜战争坐标缺口：** 旧库没有九场战役，提示词也只列锚点名称、不列坐标；`node_name`声明未被清洗函数读取。本次补入有来源与工作不确定范围的28个参考点、按当前战役选择，并实现显式锚定。仅在名称中提到目标不会把进攻部队吸到守军位置；自由部署坐标的历史偏移仍不受完整审计。详见[地理锚点说明](抗美援朝地理锚点.md)。

## 尚未解决的关键问题

**高优先级：回合时间没有程序级校验。** 真实样本设定15分钟，模型却把“1952年10月14日 拂晓前两小时”改成“1952年10月14日拂晓前一刻”。按同一拂晓参照，文本推进105分钟，而几何内核只计算15分钟。这是实际语义失败，不能被“接口200、JSON合法、名单完整”掩盖。证据：[live-timeline-check.json](../.cache/qa/acceptance-20261021/live-timeline-check.json)。后续应由程序维护结构化时钟，再生成显示文字，不能继续由模型自由改写时间。

**运行版本未同步：** 实测当前8700服务健康检查正常，但创建的空测试会话快照没有`battlefield`字段，说明它尚未加载新代码。测试会话已删除，既有会话未修改。需要先导出要保留的战局，再重启该服务加载修改；仅刷新前端不能更新Python进程。

**数据、交战规则与体验：** 已有带来源的地理参考点，仍缺少测绘核定的地形/阵地/补给坐标集；远程可达、射界遮挡与战损仍未进入统一确定性规则。长番号在密集地段会重叠；首次真实样本初始化和下一回合分别约3.4及3.8分钟，补充受控样本约48及67秒，前端没有完整的在途进度与取消入口。严格战役验证应先解决时钟，再补充可核对的初始数据与交战规则，随后做多战役、多回合稳定性测试。
