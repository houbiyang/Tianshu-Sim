# ⚖️ 裁决参数库

**一场战役一个文件。** 放进这个目录就生效，不需要注册、不需要改代码、不需要重启。

## 这个目录和 `corpus/` 的分工

| 目录 | 放什么 | 谁读 |
|---|---|---|
| `corpus/` | **史料**：时间、兵力、伤亡、出处、学界争议 | 检索（BM25），拼进 prompt |
| `adjudication/` | **尺度**：多近算接触、能封锁多宽、包围圈多深 | 几何内核，算成硬边界 |

史料回答"发生了什么"，尺度回答"物理上可能发生什么"。两者刻意分开：
史料要能引用出处，尺度是一组**可解释的估计值**，混在一起会让人误以为
"接触线 3 km"也是史书记载的。

## 加一场新战役

### 方式一：复制模板（推荐，可写注释）

```
cp adjudication/_template.md adjudication/诺曼底登陆.md
```

改里面的值，保存即可。文件名以 `_` 或 `.` 开头的不会被识别（模板就是靠这个隐藏的）。

### 方式二：一行命令

```bash
python -c "from gentactix import adjudication_lib as L; \
L.save_battle('诺曼底登陆', {'contact_km': 10, 'control_radius_km': 8, 'encircle_radius_km': 40}, era='二战')"
```

只写你想改的键，其余自动取默认值。

## 六个参数

| 键 | 默认 | 该不该按战役改 | 含义 |
|---|---|---|---|
| `contact_km` | 3.0 | **必须改** | 双方最近单位 ≤ 此距离视为接触 |
| `control_radius_km` | 3.0 | **必须改** | 敌方区域控制半径下限（射程更长时按射程算） |
| `encircle_radius_km` | 12.0 | 视规模 | 合围判定向外搜索的半径 |
| `retreat_check_km` | 12.0 | 很少改 | 退路判定向外搜索的半径 |
| `sealed_ratio_encircled` | 0.85 | 不必改 | 被封锁方向占比 ≥ 此值判「被围」 |
| `sealed_ratio_partial` | 0.50 | 不必改 | ≥ 此值判「半包围」 |

前两个是**真正会改变结论**的：弓弩射程 0.9 km 和现代火炮 20 km 差一个数量级，
用同一套"3 km 算接触"去裁决，机械化战役会把大量实际交火判成"未接触"，
而且不报错 —— 只是安静地给出错误结论。这就是本库存在的理由。

后两个比例是判定习惯（围住八成五算合围），不属于物理量，一般不用动。

## 生效顺序

1. 界面下拉框里**显式选中**的战役
2. 场景描述里**精确等于**某个战役名
3. 场景描述里**包含**某个战役名（多个命中时取名字最长的，例如「长平之战」优于「长平」）
4. `corpus/<战役名>.md` 的 frontmatter（旧位置，仍兼容）
5. 都没有 → 默认几何，界面上会注明**未标定**

⚠️ 一旦选中某个文件，**只用它那一份的值**，不会再把目录里所有文件合并。
（旧实现会把每个命中文件依次覆盖，加第二场战役时新战役会悄悄改掉老战役的参数。）

## 写错了会怎样

| 写错的内容 | 结果 |
|---|---|
| 拼错的键名（`contct_km`） | 该键被忽略，界面上报「未知参数」，其余照常生效 |
| 不是数字（`contact_km: 三公里`） | 该键被忽略并报错，其余照常生效 |
| 超出范围（`contact_km: -5`） | 同上 |
| 半包围阈值 ≥ 被围阈值 | 两个键一起退回默认，并报错 |
| 缺少结尾的 `---` | 报错，参数不生效 |

**不会静默失效**——这是刻意设计的：一个拼错的键如果被安静忽略，
使用者会以为参数已经生效，然后在错误的几何上做一整天推演。

## 自检

```bash
python verify_adjudication_lib.py
```

检查：库文件能被发现、多战役互不串味、未知键被拦、越界被拦、
旧位置（corpus）仍兼容、写回后能重新读到。
