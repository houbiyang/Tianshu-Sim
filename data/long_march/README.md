# 红军长征系列：资料与编辑入口

适用范围：1934年10月至1936年10月，中央红军、红二十五军、红四方面军、红二与红六军团四条相互关联的战线。15份场景卡覆盖战略转移、主要战斗、工程保障与会师；不是600余次战斗的完整名录。

## 使用和编辑

- [场景编辑源](scenarios.json)：部队、带精度的事件时间、统计口径、地图限制、反事实问题及裁决工作参数。
- [来源登记](sources.json)：每条来源的出版机构、链接、证据类型、适用范围和核读日期。没有声称已经查阅原始作战档案。
- [事件时间表](timeline.csv)：可用LibreOffice打开。包含单源钟点、时段和日期异文，不是自动执行脚本。
- [兵力与损失表](figures.csv)：指标、范围、报道口径分别列出；null不是零伤亡。
- [参战部队表](forces.csv)：37项部队与指挥说明；不是37支完整初始单位或已核定实力表。
- [待核证清单](verification_gaps.csv)：按场景列出数量、战术坐标和实力装备缺口，便于继续补档。
- [地名锚点](../../gentactix/long_march_anchors.json)：26处现代WGS84地名参考，附GeoNames ID、误差圈和历史地名依据。
- [共同建模约束](../../corpus/红军长征/建模与统计口径.md)：单位状态、时间、地图、兵种、因果与反事实使用规则。

修改JSON编辑源后，在项目根目录运行：

```bash
python tools/render_long_march.py
python tools/render_long_march.py --check
python verify_long_march.py
```

渲染器生成`corpus/红军长征-*.md`、`adjudication/红军长征-*.md`和四份CSV；直接改生成文件会在下次渲染时被覆盖。新增来源先登记ID，再在具体部队、事件和数字中引用。保留原作者口径，不能将争议数求均值后包装成史实。

编辑源schema v2为事件、部队和数量添加`evidence_status`：`published_account`表示公开文献记载，`source_conflict`表示异文，`teaching_window`表示教学窗口，`unverified`表示未核得。`source_locator`补充文内定位；`variant_group`标记需要择一解释的时间异文。时间精度与证据等级是两条独立维度：报道可以记到小时，但不等于查验了原始电报。异文标记是资料元数据，不会自动选择或执行历史事件。

## 核证结果与限制

湘江前后兵力差不等于该役阵亡；乌江8人是回龙场一次突击队遇难数；广义四渡赤水战果延伸至金沙江，不能全记入1月至3月；直罗镇收束采用11月24日。百丈关日期保留异文。17勇士、22人突击队的规模均不作为整场损失。

本轮审计补全后共有109条事件、9条小时级记录、48项数量记录、29项来源登记（含GeoNames）。补入乌江1月3日强渡与架桥、包座8月31日15时打援及9月1日凌晨投降异文、遵义后领导分工与两河口至俄界的指挥链。包座旧完整名称保留为别名，旧存档选择仍可解析。

公开报道、回忆转述、地方遗址说明不等于原始命令与逐人名册。官方转载也可能有错字、统计混用和日期冲突。已核到的事实与未核到的细节分别登记，不为凑齐表格补造双方伤亡、逐小时命令或战术级坐标。

后续宜核查《红军长征记》、相关军史、徐向前《历史的回顾》、杨成武长征回忆和具体纪念馆原始电报、地图、名册。本轮未逐页查阅这些书档，故不编造页码或声称完成馆藏考证。

## 软件接入边界

场景通过现有战役目录发现机制进入选择列表；启用史料检索后按所选战役限定来源，同系列共同规则可以共用，其他战役战果不能串入。锚点进入现有坐标提示，仍是地名参考。

初始化检索优先保留范围、部队和争议；预算不足时按完整段落或表格行省略，不截断数字、限定和出处。应用层史料工具采用相同规则。长征参数的`validation_status`为`teaching_estimate`，界面显示教学估计；兼容字段`calibrated`只代表已有显式配置，不代表史实校准。

本包不是保存战局JSON导入器，不包含固定的完整初始单位坐标，也未实现渡船排队、疲劳消耗、战役串联或新的DSH插件。建议从某个具体日期、局部地域开始，确认人数、地图和教学假设后再运行。已安装桌面包需要重新构建才会包含本批资料；本次不替换正在运行的用户战局。
